# Registro de cambios del proyecto

Este registro resume cinco avances documentados durante el desarrollo académico. Describe el trabajo de análisis y planificación; no implica que los módulos de software estén implementados.

1. **Definición del problema y alcance:** se estableció como objetivo organizar digitalmente la solicitud y consulta de citas médicas, identificando registro de usuarios, autenticación, horarios, gestión e historial de citas como funcionalidades previstas.
2. **Organización de requisitos e historias de usuario:** se estructuraron tareas para representar las necesidades principales del paciente y los requisitos que deben considerarse al diseñar el sistema.
3. **Modelado UML:** se trabajó en la representación del sistema mediante diagramas UML. Para consolidar la documentación se añadieron fuentes editables reconstruidas de casos de uso, clases, secuencia y actividad, además de arquitectura. Estas reconstrucciones deben compararse con los diagramas originales de Visual Paradigm antes de presentarlas como equivalentes.
4. **Definición de arquitectura inicial:** se documentó una propuesta por capas que separa frontend, backend, servicios de autenticación y acceso a datos. El Issue #12, “Definición de arquitectura inicial”, figura cerrado en GitHub.
5. **Seguimiento y preparación del cierre:** se organizaron Issues para tareas de interfaz, base de datos, validaciones, pruebas, autenticación, notificaciones, seguridad y documentación, con el propósito de identificar pendientes para las siguientes etapas. Se actualizó el README para enlazar los diagramas y explicar el estado documental del repositorio.

## Criterio de registro

Los puntos anteriores reflejan avances de análisis, diseño y gestión. Antes de afirmar que una función fue implementada o probada, debe existir evidencia técnica verificable, como código, pruebas ejecutadas o una demostración funcional.
